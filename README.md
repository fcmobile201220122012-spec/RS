# rs-brute — перебор пароля аккаунта учителя (jumanazarmirzatillayev)

Программа для перебора пароля к аккаунту учителя **Jumanaz Mirzatillayev** (`jumanazarmirzatillayev`, id=9802, группа **Kurator**, филиал "Birja oldi (Farg'ona)") на API `api.rahimovschool.uz`.

Разработана для деплоя на **Render** (бесплатный план) с управлением через **Telegram-бота**.

## Что внутри

| Файл | Назначение |
|------|------------|
| `main.py` | переборщик + HTTP-здоровье + Telegram-бот + самопинг (чтобы Render не засыпал) |
| `candidates.py` | генератор словаря (~11 000 паролей), упорядоченный по вероятности |
| `render.yaml` | конфиг деплоя на Render |
| `Procfile` / `runtime.txt` / `requirements.txt` | для Render / altri платформ |
| `state.json` | состояние прогресса (создаётся автоматически) |
| `wordlist.txt` | свой словарь (подключается через `WORDLIST`) |

## Лимиты API (важно)

Сервер ограничивает вход: **5 неудачных попыток на логин → блокировка на ~15 минут**. Программа учитывает это:
- делает не более 5 попыток за окно, затем ждёт до разблокировки;
- на `429` ждёт `retry_after` сервера и повторяет ту же попытку;
- пропускает окно, если сервер уже выдал 429.

Примерная скорость: ~5 попыток / 15 мин ≈ 480 в сутки. На 11 269 кандидатов — порядка **23 дней** при полном переборе. Поэтому словарь отсортирован от наиболее вероятных к менее вероятным.

## Деплой на Render

1. Создай бота у @BotFather, получи `TELEGRAM_BOT_TOKEN` и свой `TELEGRAM_CHAT_ID` (напиши боту что-нибудь, либо через @userinfobot).
2. Залей содержимое папки `rs-brute/` в репозиторий (GitHub/GitLab).
3. На Render создай **Web Service** из репо, в настройках укажи переменные окружения:
   - `TELEGRAM_BOT_TOKEN` — токен бота
   - `TELEGRAM_CHAT_ID` — твой chat-id
   - `TARGET_USERNAME` — `jumanazarmirzatillayev` (уже в `render.yaml`)
   - `RENDER_EXTERNAL_URL` — Render добавит автоматически (нужен для самопинга)
4. Деплой: `buildCommand: pip install -r requirements.txt`, `startCommand: python main.py`.

Бесплатный план Render засыпает через 15 мин без входящих запросов — программа сама себе делает `/health` пинг каждые 10 мин (`SELF_PING_SECS`), чтобы держать процесс живым. Надёжнее дополнительно повесить внешний аптайм-монитор (UptimeRobot и т.п.) на `https://<сервис>.onrender.com/health`.

## Управление через Telegram-бот

Команды (работают только от `TELEGRAM_CHAT_ID`):

| Команда | Что делает |
|---------|------------|
| `/start` | приветствие и список команд |
| `/status` | прогресс, индекс, примерный ETA |
| `/pause` | приостановить перебор |
| `/resume` | продолжить |
| `/password` | показать найденный пароль (если найден) |
| `/attempts` | сколько проверено |
| `/skip` | пропустить текущего кандидата |
| `/test <пароль>` | проверить конкретный пароль прямо сейчас |

Когда пароль находится, бот присылает его в чат с токеном доступа.

## Локальный запуск (отладка)

```bash
cd rs-brute
cp .env.example .env
# укажи TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID в .env
pip install -r requirements.txt

# посмотреть словарь (не шлёт запросы к API)
python main.py --list-only | head -20

# одна пробная попытка (тратит 1 из 5 допустимых!)
python main.py --once

# полный запуск
python main.py
```

## Сохранение прогресса

Прогресс пишется в `state.json` (текущий индекс, найденный пароль, пауза). При перезапуске Render состояние восстанавливается из этого файла. Если нужен чистый старт — удалите `state.json` перед деплоем.
